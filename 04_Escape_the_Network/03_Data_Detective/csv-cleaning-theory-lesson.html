1. What a CSV record means

A media club loans equipment. Each row is one loan observation, identified by a loan_id. This is a different dataset from your game project, but the same cleaning ideas apply.

Our six fields are loan_id, borrower, item, units, days and returned. Values initially arrive as text. A header names the columns; it is not a data row.

loan_id,borrower,item,units,days,returned
L1,Ada,Camera,2,3,true
L9,"Hall, Ada",Mic,1,2,false

The quoted name Hall, Ada is one field despite containing a comma. A CSV parser respects quotes; simply splitting at each comma does not. In Python, csv.DictReader maps each column name to its value.

Missing files or wrong headers are import problems. Bad values in an individual record should be logged with a source line and reason.

2. Normalise before deciding

Normalisation fixes valid formatting differences: trim surrounding spaces, recognise Camera/camera as the same allowed item, and map TRUE/false to actual booleans. It does not invent a missing name or replace invalid numbers with zero.

Here the allowed items are Camera, Tripod and Mic. Units must be a whole number from 0 to 10, days from 0 to 30, and returned must be true or false. IDs and borrower names must be non-empty and remain case-sensitive.

Try camera with spaces, then an unknown item, a decimal quantity or yes as returned.

Watch out: the text "false" is non-empty, so a generic truthiness test would call it true. Compare the allowed words explicitly before conversion. A high value within the stated range is valid.

4. Identical and conflicting duplicates

After normalisation, L1 has two identical valid copies. Keep one and reject the extra copy; otherwise that loan contributes twice to the statistics.

L3 has two valid copies with different quantities. Quarantine both copies. Keeping the first still allows unreliable evidence into your analysis. An invalid copy is rejected for its validation error; it does not automatically invalidate a separate valid copy.

Audit rule: loaded = accepted + rejected. Count each data record once, even when it has several problems. The header is excluded. For this lab: 8 loaded, 3 accepted and 5 rejected.

5. Aggregate with the right denominator

Use accepted records only. Group them by item before calculating each group’s statistics. A mean is the group total divided by that group’s record count. Return percentage is returned records divided by group records, multiplied by 100.

Ada’s two accepted Camera records have units 2 and 4, with one returned and one not returned. Predict the mean units and return percentage.

An empty Tripod group is no data, not evidence of a measured 0% return rate. Division by zero needs a deliberate rule. Keep full precision during calculations and round for display.

Flags need a rule and a sample size

Suppose a flag means mean units strictly above 4, with at least 5 accepted records. Try the boundaries below. A flag requests investigation; it does not prove misuse.

6. Export evidence and interpret cautiously

Keep the source file unchanged. Export clean records with the original column names, rejected records with original fields plus source_line and reason, and labelled summary statistics. Reopen the exports to check their counts and values.

The downloads use the lab’s correct cleaning policy, regardless of which stage is currently displayed. Open them to inspect the evidence.

A difference between groups is an observed association. It does not establish that the item caused a borrower to return equipment. Small samples, different borrowers and loan circumstances could explain it.
